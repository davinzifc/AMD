### Fase 4: Validacion Cedula Duplicada en Tiempo Real (US-013)

**Patron identico a NIT** de config-empresa:
- Signal `cedulaError = signal<string | null>(null)`
- Signal `cedulaChecking = signal(false)`
- `onCedulaBlur()`:
  - Si vacio: limpiar error
  - Si editando y cc_id == original: limpiar error
  - Llamar `firmante.service.getFirmanteByCcId(cc_id)`
  - Si existe: `cedulaError.set('La cedula CC XXXXX ya esta registrada para el firmante "NOMBRE"')`
  - Input con borde rojo via `[class.cedula-error]="cedulaError()"`
  - Boton Guardar deshabilitado si `cedulaError()` truthy

### Fase 5: Modal Ver Detalle con Blur de Seguridad (US-016)

**Este es el feature unico de este modulo.**

**Segundo p-dialog** para detalle (read-only):
- Header: "Informacion del Firmante"
- Ancho: 600px (mas ancho que empresa para acomodar firma horizontal)
- Modal: true, dismissableMask: true

**Contenido con p-card**:
- **Seccion firma** (parte superior):
  - Contenedor clickeable `firma-wrapper` (cursor: pointer)
  - Imagen con `[class.blurred]="firmaBlurred()"` → `filter: blur(12px)`
  - Overlay superpuesto (solo visible cuando blurred):
    - Icono `pi pi-eye` (2rem)
    - Texto "Click para visualizar la firma"
    - `pointer-events: none` (para que click llegue al wrapper)
  - Transicion CSS: `transition: filter 0.4s ease-in-out`
  - Sin imagen: placeholder con `pi-image` + texto "Sin imagen de firma" (SIN blur)
- **p-divider** separador
- **Info rows** (patron identico a empresa):
  - pi-user → Nombre Completo: valor
  - pi-id-card → Cedula / Identificacion: valor
- Footer: solo boton "Cerrar"

**Logica de blur**:
- `firmaBlurred = signal(true)` — siempre inicia con blur
- `toggleBlur()` → `firmaBlurred.set(false)` (one-way: solo quita blur)
- `onDetailModalClose()` → resetea `firmaBlurred.set(true)` (restaura blur)
- `openDetailModal(firmante)` → siempre setea `firmaBlurred.set(true)` + carga imagen

### Fase 6: Confirmacion de Actualizacion (US-018)

**Flujo** (identico a empresa):
1. Usuario modifica datos y click "Actualizar"
2. ConfirmationService: "¿Estas seguro de que deseas actualizar los datos del firmante [NOMBRE]?"
3. Botones: "Si, actualizar" (primario) + "Cancelar" (secundario)
4. Confirma → ejecutar update, cerrar modal, toast success
5. Cancela → volver al modal de edicion

### Fase 7: Eliminacion con Confirmacion (US-020)

**Flujo** (identico a empresa):
1. Click icono pi-trash en tabla
2. ConfirmationService: "¿Eliminar al firmante [NOMBRE] (CC [CEDULA])? Esta accion no se puede deshacer."
3. Boton "Eliminar" con `acceptButtonStyleClass: 'p-button-danger'`
4. Confirma → delete, toast success, tabla se actualiza
5. Cancela → nada

### Fase 8: Mensajes de Feedback (US-019)

**Todos via NotificationService** (ya existente):
- Crear: `success('Firmante creado exitosamente')`
- Actualizar: `success('Firmante actualizado correctamente')`
- Eliminar: `success('Firmante eliminado correctamente')`
- Cedula duplicada: `error('La cedula/identificacion ingresada ya existe en el sistema')`
- Error imagen formato: `error('Formato no valido', 'Solo se permiten archivos PNG o JPG')`
- Error imagen tamanio: `error('Archivo muy grande', 'El tamano maximo permitido es 2MB')`
- Campos obligatorios: `warn('Campos obligatorios', 'Por favor, completa todos los campos obligatorios')`
- Error red: `error('Error de conexion', 'Por favor, intenta nuevamente')`

- **Depth**: Borders-only (1px solid #e2e8f0), sin shadows
- **Acento**: #3b82f6 (azul institucional)
- **Fondo pagina**: #f8fafc
- **Cards/Tabla**: #ffffff con border
- **Texto primario**: #0f172a
- **Texto secundario**: #64748b
- **Spacing**: Base 8px (8, 16, 24, 32)
- **Border radius**: 8px contenedores, 6px inputs
