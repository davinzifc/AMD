# Plan: Refactorización de Componentes Angular — Split Files + Mover Módulos Independientes

## Contexto

Todos los componentes Angular del proyecto están creados como single-file (template + styles inline en el `.ts`). Esto dificulta el mantenimiento, especialmente en componentes grandes como `config-empresa.page.ts` (1015 líneas) y `config-firmante.page.ts` (946 líneas).

Además, `config-empresa` y `config-firmante` son módulos de configuración independientes que están incorrectamente ubicados dentro de `certificados-crypto/pages/`. Deben ser features independientes bajo `tools/`.

**Resultado esperado:** Todos los componentes con archivos separados (.ts, .html, .scss) y los módulos de configuración en su ubicación correcta como features independientes.

## Fase 2: Mover servicios y modelos compartidos a `shared/`

Los servicios `empresa.service.ts` y `firmante.service.ts` son usados tanto por las páginas de config como por el flujo principal de crypto. Al separar los módulos, estos deben vivir en `shared/`.

### 2.1 Crear `shared/models/empresa.model.ts`
- Extraer interfaces `Empresa`, `CreateEmpresaDto`, `UpdateEmpresaDto` desde `empresa.service.ts` (líneas 4-27)
- El service importará desde el nuevo model file

### 2.2 Mover `firmante.model.ts` → `shared/models/firmante.model.ts`
- Desde: `certificados-crypto/models/firmante.model.ts`
- Hacia: `shared/models/firmante.model.ts`

### 2.3 Mover `empresa.service.ts` → `shared/services/empresa.service.ts`
- Actualizar import de interfaces al nuevo model file
- Re-exportar tipos para compatibilidad: `export { Empresa, ... } from '../models/empresa.model'`

### 2.4 Mover `firmante.service.ts` → `shared/services/firmante.service.ts`
- Actualizar import de `firmante.model` a nueva ruta relativa
- Re-exportar tipos: `export { FirmanteListItem, ... } from '../models/firmante.model'`

### 2.5 Actualizar imports en archivos que referencian las rutas antiguas

| Archivo | Cambio de import |
