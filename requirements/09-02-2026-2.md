# Historias de Usuario - Módulo de Configuración de Firmantes

## Contexto del Módulo

Este módulo permite administrar los firmantes disponibles para los certificados. Incluye funcionalidades similares al módulo de empresas pero adaptado a las necesidades específicas de gestión de firmantes con medidas de seguridad adicionales para proteger información sensible como imágenes de firma.

---

## US-011: Rediseño de la Interfaz de Configuración de Firmantes

### Descripción
Como administrador del sistema, quiero una interfaz profesional y organizada para la gestión de firmantes, para mejorar la experiencia de usuario y la eficiencia en la administración de datos sensibles.

### Criterios de Aceptación

#### AC1: Estado Inicial de la Interfaz
- **DADO** que ingreso a la sección "Configuración de Firmantes"
- **CUANDO** la página se carga por primera vez
- **ENTONCES** no debo ver los campos de formulario visibles en la pantalla
- **Y** debo ver únicamente un botón claramente visible con la acción "Agregar Firmante" o "Nuevo Firmante"

#### AC2: Visualización de Firmantes Registrados
- **DADO** que existen firmantes registrados en el sistema
- **CUANDO** accedo a la sección de configuración
- **ENTONCES** debo ver una tabla con las siguientes columnas:
  - Nombre completo
  - Cédula/Identificación
  - Acciones
- **Y** la tabla debe estar ordenada por nombre completo por defecto
- **Y** debe incluir funcionalidad de búsqueda y filtrado
- **Y** NO debe mostrar la imagen de firma en la tabla (solo se visualiza en el modal "Ver más")

---

## US-012: Creación de Firmante mediante Modal

### Descripción
Como administrador del sistema, quiero crear nuevos firmantes mediante un popup modal, para tener un flujo de trabajo más limpio y organizado.

### Criterios de Aceptación

#### AC1: Apertura del Modal de Creación
- **DADO** que estoy en la sección de configuración de firmantes
- **CUANDO** hago clic en el botón "Agregar Firmante"
- **ENTONCES** debe abrirse un modal/popup centrado en la pantalla
- **Y** el modal debe tener un título claro: "Crear Nuevo Firmante"
- **Y** debe mostrarse una capa de fondo oscuro (overlay) que bloquee la interacción con el resto de la página

#### AC2: Campos del Formulario
El modal debe contener los siguientes campos:
- **Nombre completo** (obligatorio)
- **Cédula / Identificación** (obligatorio)
- **Imagen de firma** (obligatorio)

#### AC3: Botones de Acción
- **Guardar/Crear**: Botón primario para confirmar la creación
- **Cancelar**: Botón secundario para cerrar el modal sin guardar
- **X (cerrar)**: Icono en la esquina superior derecha del modal

#### AC4: Comportamiento del Modal
- **DADO** que el modal está abierto
- **CUANDO** hago clic en "Cancelar", presiono ESC o hago clic en el overlay
- **ENTONCES** el modal debe cerrarse sin guardar cambios
- **Y** debe mostrar un mensaje de confirmación si hay datos sin guardar: "¿Estás seguro de que deseas salir sin guardar?"

## US-013: Validación de Cédula/Identificación Duplicada

### Descripción
Como administrador del sistema, quiero ser notificado cuando intente crear un firmante con una cédula/identificación que ya existe, para evitar duplicados en la base de datos.

### Criterios de Aceptación

#### AC1: Validación en Tiempo Real
- **DADO** que estoy llenando el formulario de creación de firmante
- **CUANDO** ingreso una cédula/identificación en el campo correspondiente y salgo del campo (onBlur)
- **ENTONCES** el sistema debe validar si esa identificación ya existe en la base de datos
- **Y** debe mostrar un mensaje de advertencia debajo del campo: "⚠️ Esta cédula/identificación ya está registrada en el sistema"
- **Y** el campo debe marcarse visualmente con un borde rojo

#### AC2: Bloqueo de Creación
- **DADO** que he ingresado una cédula/identificación duplicada
- **CUANDO** intento hacer clic en el botón "Guardar"
- **ENTONCES** el botón debe estar deshabilitado
- **O** debe mostrar un mensaje de error: "No se puede crear el firmante. La cédula/identificación ingresada ya existe."

#### AC3: Mensaje de Confirmación
- **DADO** que el sistema detecta una cédula/identificación duplicada
- **ENTONCES** debe mostrar el nombre del firmante existente con esa identificación
- **EJEMPLO**: "La cédula CC 290048 ya está registrada para el firmante Leidy Yurani Villamil"

## US-014: Previsualización de Imagen de Firma antes de Crear

### Descripción
Como administrador del sistema, quiero previsualizar la imagen de firma antes de guardar, para asegurarme de que la imagen es correcta.

### Criterios de Aceptación

#### AC1: Carga de Imagen
- **DADO** que estoy en el formulario de creación de firmante
- **CUANDO** hago clic en el área de carga de imagen de firma
- **ENTONCES** debe abrirse el explorador de archivos del sistema operativo
- **Y** debe permitir seleccionar únicamente archivos PNG y JPG
- **Y** debe mostrar un mensaje si el formato no es válido: "Solo se permiten archivos PNG o JPG"

#### AC2: Validación de Tamaño
- **DADO** que selecciono un archivo de imagen
- **CUANDO** el archivo pesa más de 2MB
- **ENTONCES** debe mostrar un mensaje de error: "El tamaño máximo permitido es 2MB"
- **Y** no debe cargar la imagen

#### AC3: Previsualización
- **DADO** que he seleccionado una imagen válida
- **CUANDO** la imagen se carga
- **ENTONCES** debe mostrarse una previsualización de la imagen en el modal
- **Y** debe incluir un botón "Cambiar imagen" o icono de eliminar (X) para seleccionar otra imagen
- **Y** la previsualización debe mantener las proporciones de la imagen original
- **Y** debe mostrarse en un área de 200x100px (aproximadamente, formato firma)

## US-015: Visualización de Firmantes en Tabla

### Descripción
Como administrador del sistema, quiero ver los firmantes registrados en formato de tabla limpia y simple, para tener una mejor visualización y gestión de la información.

### Criterios de Aceptación

#### AC1: Estructura de la Tabla
- **DADO** que existen firmantes registrados
- **CUANDO** accedo a la sección de configuración de firmantes
- **ENTONCES** debo ver una tabla con las siguientes columnas:
  1. **Nombre Completo**
  2. **Cédula / Identificación**
  3. **Acciones** (columna fija a la derecha)
- **Y** NO debe incluir una columna para la imagen de firma
- **Y** la imagen solo debe visualizarse cuando se acceda a "Ver más información"

#### AC2: Funcionalidades de la Tabla
La tabla debe incluir:
- Paginación (10, 25, 50 registros por página)
- Búsqueda global (busca en nombre completo y cédula)
- Ordenamiento por columnas (clic en encabezado)
- Indicador de "No hay datos" cuando no existen registros

#### AC3: Diseño Responsive
- **DADO** que accedo desde un dispositivo móvil
- **ENTONCES** la tabla debe adaptarse mostrando las columnas más importantes
- **O** debe convertirse en cards verticales con toda la información

#### AC4: Columna de Acciones
- **DADO** que estoy viendo la tabla
- **CUANDO** observo la columna "Acciones"
- **ENTONCES** debe mostrar botones/iconos para:
  - Ver más información (ícono de ojo o info)
  - Editar (ícono de lápiz)
  - Eliminar (ícono de papelera - opcional)
- **Y** los botones deben tener tooltips descriptivos al hacer hover

## US-016: Modal "Ver Más Información" con Firma Protegida (Blur de Seguridad)

### Descripción
Como administrador del sistema, quiero ver los detalles completos de un firmante incluyendo su imagen de firma con medidas de seguridad (blur), para proteger información sensible y solo visualizarla cuando sea necesario.

### Criterios de Aceptación

#### AC1: Botón de Acción en la Tabla
- **DADO** que estoy viendo la tabla de firmantes
- **CUANDO** observo la columna "Acciones"
- **ENTONCES** debe haber un botón o icono de "Ver más" / "Información" (ej: ícono de ojo 👁️)
- **Y** debe tener un tooltip que diga "Ver información completa" al hacer hover

#### AC2: Apertura del Modal de Información
- **DADO** que hago clic en el botón "Ver más información"
- **CUANDO** se abre el modal
- **ENTONCES** debe mostrarse un popup con el título "Información del Firmante"
- **Y** debe usar el componente modal reutilizable
- **Y** debe tener un ancho apropiado (600px o '60vw')

#### AC3: Contenido del Modal con Imagen de Firma en Blur (Estado Inicial)
- **DADO** que el modal está abierto
- **ENTONCES** debe mostrar los siguientes datos usando `p-card` de PrimeNG:
  - **Imagen de firma**: Mostrada con efecto **blur** (desenfocada) por seguridad
  - **Mensaje superpuesto sobre la imagen**: "🔒 Click para visualizar la firma" o "👁️ Haz clic para ver"
  - **Nombre completo**: Texto destacado
  - **Cédula / Identificación**: Con formato legible
- **Y** si el firmante NO tiene imagen de firma, debe mostrar un placeholder/icono genérico
- **Y** cada campo debe tener una etiqueta clara (label)

#### AC4: Estado de la Imagen con Blur (Protección de Seguridad)
- **DADO** que el modal se abre por primera vez
- **CUANDO** observo la sección de imagen de firma
- **ENTONCES** la imagen debe tener aplicado un efecto de desenfoque (blur) CSS
- **Y** debe tener un filtro de `filter: blur(10px)` o similar
- **Y** debe mostrarse un mensaje/overlay superpuesto: "🔒 Click para visualizar"
- **Y** el área de la imagen debe ser interactiva (cursor pointer)
- **Y** debe tener un borde o indicador visual que sugiera que es clickeable

#### AC5: Visualización de Firma sin Blur (Click para Desbloquear)
- **DADO** que veo la imagen de firma con blur
- **CUANDO** hago clic sobre el área de la imagen
- **ENTONCES** el efecto de blur debe removerse instantáneamente
- **Y** el mensaje "🔒 Click para visualizar" debe desaparecer
- **Y** la imagen debe mostrarse con claridad completa
- **Y** debe permanecer visible sin blur hasta que se cierre el modal
- **Y** NO debe volver a aplicarse el blur mientras el modal esté abierto

#### AC6: Restablecer Blur al Cerrar Modal
- **DADO** que he quitado el blur de la imagen
- **CUANDO** cierro el modal (con botón "Cerrar", X o ESC)
- **Y** vuelvo a abrir el modal del mismo firmante
- **ENTONCES** la imagen debe volver a mostrarse con blur por defecto
- **Y** debe requerir nuevamente un clic para visualizarla sin blur

#### AC7: Diseño Visual del Modal
El modal debe:
- Usar `p-card` de PrimeNG para estructurar la información
- Mostrar la imagen de firma en la parte superior del card
- Usar `p-divider` para separar secciones visualmente
- Tener un diseño limpio con espaciado adecuado
- Incluir iconos descriptivos junto a cada campo

**Ejemplo de estructura sugerida:**
```html
<p-dialog header="Información del Firmante" [visible]="true" [modal]="true">
  <p-card>
    <div class="firmante-detalle">
      <!-- Imagen de firma con blur inicial -->
      <div class="firma-container" (click)="toggleBlur()">
        <img 
          [src]="firmante.imagenFirma" 
          alt="Firma" 
          [class.blurred]="firmaBlurred"
          class="firma-image"/>

        <!-- Overlay con mensaje cuando está blurred -->
        <div *ngIf="firmaBlurred" class="blur-overlay">
          <i class="pi pi-eye"></i>
          <p>Click para visualizar la firma</p>
        </div>
      </div>

      <p-divider></p-divider>

      <!-- Información del firmante -->
      <div class="info-row">
        <span class="label"><i class="pi pi-user"></i> Nombre Completo:</span>
        <span class="value">{{ firmante.nombreCompleto }}</span>
      </div>

      <div class="info-row">
        <span class="label"><i class="pi pi-id-card"></i> Cédula / Identificación:</span>
        <span class="value">{{ firmante.cedula }}</span>
      </div>
    </div>
  </p-card>

  <ng-template pTemplate="footer">
    <p-button label="Cerrar" icon="pi pi-times" (onClick)="cerrar()"></p-button>
  </ng-template>
</p-dialog>
```

**CSS requerido:**
```css
.firma-container {
  position: relative;
  cursor: pointer;
  display: flex;
  justify-content: center;
  margin-bottom: 1rem;
}

.firma-image {
  max-width: 300px;
  max-height: 150px;
  border: 2px solid #e0e0e0;
  border-radius: 8px;
  transition: filter 0.3s ease;
}

.firma-image.blurred {
  filter: blur(10px);
}

.blur-overlay {
  position: absolute;
  top: 50%;
  left: 50%;
  transform: translate(-50%, -50%);
  text-align: center;
  color: #333;
  font-weight: bold;
  pointer-events: none;
}

.blur-overlay i {
  font-size: 2rem;
  display: block;
  margin-bottom: 0.5rem;
}
```

#### AC8: Botones del Modal
- **DADO** que estoy viendo la información completa
- **ENTONCES** el modal debe tener únicamente un botón "Cerrar"
- **Y** NO debe haber opciones de edición en este modal (solo lectura)
- **Y** debe poder cerrarse presionando ESC o haciendo clic en la X del header

#### AC9: Caso sin Imagen de Firma
- **DADO** que el firmante NO tiene una imagen de firma guardada
- **CUANDO** abro el modal de información
- **ENTONCES** debe mostrarse un icono placeholder (ej: `pi pi-file` de PrimeNG o una imagen por defecto)
- **Y** debe indicar visualmente que no hay firma disponible
- **Y** NO debe aplicarse el efecto blur (no tiene sentido si no hay imagen)

#### AC4: Configuración de Toast

- Posición: top-right o top-center
- Cerrable manualmente (con X)

## Requisitos Técnicos

### Tecnologías Sugeridas
- **Framework Frontend**: Angular
- **Librería de Componentes**: PrimeNG
  - `p-dialog` para modales
  - `p-table` para tablas
  - `p-card` para tarjetas de información
  - `p-toast` para notificaciones
  - `p-confirmDialog` para confirmaciones
  - `p-fileUpload` para carga de imágenes
  - `p-button` para botones
  - `p-divider` para separadores visuales

### Validaciones a Implementar
1. Validación de campos obligatorios (frontend y backend)
2. Validación de formato de cédula/identificación
3. Validación de tipo y tamaño de archivo de imagen
4. Validación de duplicados de cédula (backend)
5. Sanitización de nombres (sin caracteres especiales peligrosos)

### Consideraciones de Seguridad Específicas
1. **Protección de imagen de firma con blur**:
   - Aplicar blur por defecto al abrir modal de información
   - Requiere acción explícita (click) para visualizar sin blur
   - Restablecer blur al cerrar modal
2. **Almacenamiento seguro**:
   - Imágenes de firma deben almacenarse encriptadas en el backend
   - Transmisión mediante HTTPS obligatorio
3. **Control de acceso**:
   - Solo usuarios con permisos específicos pueden ver firmantes
   - Auditoría de quién visualiza las firmas y cuándo
4. **Protección XSS**:
   - Validación y sanitización de inputs
   - Escape de caracteres especiales

### Consideraciones de UX
- Tiempos de carga: Mostrar spinners en operaciones asíncronas
- Accesibilidad: Labels asociados a inputs, navegación por teclado
- Responsive: Diseño adaptable a mobile, tablet y desktop
- Feedback visual: Estados hover, focus, disabled en botones
- Animaciones sutiles en modales y transición de blur
- Tooltips informativos en botones de acción
- **Indicador visual claro** de que la imagen tiene blur y es clickeable

## Casos de Prueba

### CP-008: Crear firmante con datos válidos
**Pasos:**
1. Clic en "Agregar Firmante"
2. Llenar todos los campos obligatorios
3. Seleccionar imagen de firma válida
4. Verificar previsualización de la imagen
5. Clic en "Guardar"

**Resultado Esperado:** Firmante creado, modal cerrado, mensaje de éxito, tabla actualizada

### CP-009: Intentar crear firmante con cédula duplicada
**Pasos:**
1. Clic en "Agregar Firmante"
2. Ingresar cédula existente (ej: CC 290048)
3. Llenar demás campos
4. Intentar guardar

**Resultado Esperado:** Mensaje de error, botón deshabilitado, no se crea el firmante

### CP-010: Ver información con firma en blur (seguridad)
**Pasos:**
1. En la tabla, clic en botón "Ver más" (ojo) del firmante
2. Verificar que se abre el modal
3. Observar la imagen de firma

**Resultado Esperado:** 
- Modal abierto con card de PrimeNG
- Imagen de firma visible con **efecto blur aplicado**
- Mensaje superpuesto: "🔒 Click para visualizar la firma"
- Área de imagen debe tener cursor pointer
- Datos del firmante visibles sin blur

### CP-011: Quitar blur de firma mediante click
**Pasos:**
1. Abrir modal de información de un firmante
2. Verificar que la firma tiene blur
3. Hacer clic sobre la imagen de firma

**Resultado Esperado:** 
- Efecto blur se remueve instantáneamente
- Mensaje de "Click para visualizar" desaparece
- Imagen se muestra con claridad total
- Imagen permanece sin blur hasta cerrar el modal

### CP-012: Restablecer blur al reabrir modal
**Pasos:**
1. Abrir modal y quitar blur haciendo clic
2. Cerrar el modal
3. Volver a abrir el modal del mismo firmante

**Resultado Esperado:** 
- Imagen vuelve a mostrarse con blur por defecto
- Requiere nuevamente clic para visualizar sin blur

### CP-013: Ver información sin imagen de firma
**Pasos:**
1. Crear un firmante sin imagen de firma
2. Clic en "Ver más"
3. Verificar el modal

**Resultado Esperado:** 
- Modal muestra placeholder/icono genérico
- NO se aplica efecto blur (no hay imagen)
- Resto de datos visibles normalmente

### CP-014: Editar firmante y confirmar cambios
**Pasos:**
1. Clic en "Editar" en un firmante
2. Modificar nombre
3. Clic en "Actualizar"
4. Confirmar en el modal

**Resultado Esperado:** Firmante actualizado, modales cerrados, mensaje de éxito

1. Acceder a configuración de firmantes
2. Observar la tabla

**Resultado Esperado:**

## Flujo de Interacción: Ver Firma con Blur de Seguridad

### Secuencia de Eventos Detallada
1. Usuario visualiza la tabla con firmantes (solo Nombre, Cédula, Acciones)
2. Usuario hace clic en el botón "Ver más" (👁️) en la columna Acciones
3. Se abre un popup/modal centrado
4. El modal muestra un `p-card` con:
   - **Imagen de firma con blur aplicado** (`filter: blur(10px)`)
   - **Overlay superpuesto** con mensaje "🔒 Click para visualizar la firma"
   - Cursor cambia a pointer al pasar sobre la imagen
   - Datos del firmante visibles (nombre, cédula) **sin blur**
5. Usuario hace clic sobre la imagen de firma
6. **Transición suave**: Blur se remueve (`filter: blur(0px)`) con animación CSS
7. Overlay con mensaje desaparece
8. Imagen se muestra con claridad completa
9. Usuario revisa la información
10. Usuario cierra el modal
11. Al reabrir el modal, la firma vuelve a estar con blur (estado por defecto)

## Implementación Técnica del Blur de Seguridad

### Componente TypeScript (Ejemplo)
```typescript
export class FirmanteDetalleComponent {
  firmante: Firmante;
  firmaBlurred: boolean = true; // Estado inicial con blur

  // Toggle blur al hacer click
  toggleBlur(): void {
    this.firmaBlurred = false;
  }

  // Restablecer blur al cerrar
  cerrarModal(): void {
    this.firmaBlurred = true;
    this.displayModal = false;
  }

  // Restablecer blur al abrir modal
  verDetalles(firmante: Firmante): void {
    this.firmante = firmante;
    this.firmaBlurred = true; // Resetear a blur por defecto
    this.displayModal = true;
  }
}
```

## Notas Adicionales

### Diferencias Clave vs Módulo de Empresas
1. **Seguridad de imagen**: Blur obligatorio en visualización de firma (no aplica en empresas)
2. **Campos simplificados**: Solo nombre y cédula (empresas tiene más campos)
3. **Imagen obligatoria**: La firma es requerida (logo de empresa es opcional)
4. **Formato de imagen**: Horizontal para firmas vs cuadrado para logos
5. **Auditoría**: Registro de visualizaciones de firma (mayor control)

### Mejoras Futuras (Backlog)
- Carga de múltiples firmas por firmante (firma digital, firma manual)
- Versiones históricas de firmas
- Validación de autenticidad de firma
- Integración con firmas digitales certificadas
- Exportar listado de firmantes a PDF cifrado
- Estadísticas de uso de firmas en certificados
- Caducidad de firmas (renovación periódica)

### Dependencias
- API REST endpoints para CRUD de firmantes
- Servicio de almacenamiento seguro para imágenes (encriptación)
- Sistema de auditoría para registrar visualizaciones
- Permisos y roles de usuario configurados
- Certificados SSL/TLS para transmisión segura

### Riesgos Identificados
1. **Seguridad de imágenes**: Firmas son información sensible
   - Mitigación: Encriptación en reposo, blur por defecto, auditoría de acceso
2. **Rendimiento**: Blur CSS puede afectar dispositivos antiguos
   - Mitigación: Optimizar transiciones, lazy loading de imágenes
3. **Cumplimiento legal**: Almacenamiento de firmas debe cumplir regulaciones
   - Mitigación: Consultar con equipo legal, implementar retención de datos
4. **Tamaño de archivos**: Firmas de alta resolución pueden ser pesadas
   - Mitigación: Compresión automática, límite de 2MB
