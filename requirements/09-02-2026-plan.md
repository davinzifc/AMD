### Fase 3: Validacion NIT Duplicado en Tiempo Real (US-003)
**Archivos**:
- `src/app/tools/certificados-crypto/services/empresa.service.ts` — agregar metodo
- `config-empresa.page.ts` — logica onBlur

**Cambios en EmpresaService**:
```typescript
async checkNitExists(nit: string, excludeNit?: string): Promise<Empresa | null>
```
- Usa `getEmpresaByNit` existente (Rust ya lo tiene)
- Si `excludeNit` coincide con el NIT buscado, retorna null (es la misma empresa editandose)

**Logica en componente**:
- Signal `nitError = signal<string | null>(null)` para mensaje de error
- Signal `nitChecking = signal(false)` para loading indicator
- `onNitBlur()`:
  - Si NIT vacio: limpiar error
  - Si editando y NIT == originalNit: limpiar error
  - Llamar `checkNitExists(nit, editando ? originalNit : undefined)`
  - Si existe: `nitError.set('El NIT XXX ya esta registrado para la empresa "NOMBRE"')`
  - Input con borde rojo via `[class.nit-error]="nitError()"`
  - Boton Guardar deshabilitado si `nitError()` es truthy

### Fase 5: Confirmacion de Actualizacion (US-009)
**Archivo**: `config-empresa.page.ts`

**Flujo**:
1. Usuario modifica datos y click "Actualizar"
2. ConfirmationService muestra: "¿Estas seguro de que deseas actualizar los datos de la empresa [NOMBRE]?"
3. Botones: "Si, actualizar" (primario) + "Cancelar" (secundario)
4. Si confirma: ejecutar update, cerrar ambos modals, toast success
5. Si cancela: volver al modal de edicion con datos sin guardar
